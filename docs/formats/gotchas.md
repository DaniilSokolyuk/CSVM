# Format gotchas, the ones that bite constantly

Cross-cutting facts about the extracted data that trip up every fresh reader or renderer
implementation. Each bullet states the fact plus the consequence for an implementation
(consequences are phrased against CSVM's Godot engine where that makes them concrete);
the per-format detail lives in the page each bullet links. Read this page before writing
any reader, transform, or shader code.

- `nodes.json` `children`/`parent` are **flat list positions**, NOT the `node_index` field (node_index has duplicates).
- Euler `transformation.rotation` composes **R = Ry(y)·Rx(x)·Rz(z)** = Godot's `EulerOrder.Yxz`; when `matrix` is present it wins and is stored **transposed**.
- Coordinates are right-handed Y-up with the nose at **−Z**, Godot's frame exactly; no mirroring, no UV V-flip. **Anim-def `AT_NODE`/`PUFFER_STATE` offsets are in that same frame, verbatim, no axis swap** (censused over all 6,728 in the install, the retired `analysis/at-node-axis-order/`, `git show analysis-archive:analysis/at-node-axis-order/FINDINGS.md`; see [anim-definitions.md](anim-definitions.md)). An effect that renders metres above where you expected it is authored that way; the question is where its host was staged, not which axis is up.
- `meshes.json` has `null` entries, keep them to preserve `mesh_index` alignment.
- **Weather/horizon zone names are per chapter, not a fixed pair:** C1–C4 ship `zone1`+`zone2`, **C5 ships `zone1`+`zone3`**. Never hardcode the pair, see [weather.md](weather.md).
- Texture name quirks: fixed-width 20-char truncation (prefix-match), mech3ax duplicate renames (strip `.-N` suffix), and, fork extraction only, trailing doubled periods on empty-suffix names (`bldhwk_cowling..tif` → strip trailing periods before matching; see [gamez.md](gamez.md)). Plane skin pixels are in each chapter's `texture.zbd`, not planes.zbd.
- **Plane skins ship unpainted.** They are shading maps carrying paint-region keys; the engine recolours them with the scheme's `paint_color1..3` at load time. The region masks are in `crimson.rof`: three per-pattern, per-skin weight masks summing to 255 ([rof.md](rof.md)), applied by `PlanePainter`. `*_noselogo`/`*_taillogo`/`*_winglogo` are 16×16 placeholders, not artwork; the real decal is one of the numbered 00–49 textures selected by `paint_decalN` (not every plane has all three: no `fir_noselogo`).
- Per-corner `vertex_colors` = **baked lighting** (really an AO/shadow mask, 70% pure white, 30% darker): the world renders fullbright (texture × vertex color); shaded comes out murky-dark. Some polys are baked pure black on purpose (painted shadows). **The multiply is gamma-space:** the original DX7 engine multiplied texture × vertex color in sRGB space; a linear-space multiply washes out the baked-dark corners, so the fullbright shaders linearise the vertex color first (`SrgbToLinearFn`). On top of the vertex colors the original applies the mission's **SUNLIGHT** (weather.json) as a per-mission brightness, the remake's `csky_world_light`. ⚠ **But not to every model: `flags.lighting: false` opts a model out of that brightness entirely** (3,003 models install-wide, sprite cards, clutter trees, glows, effect meshes, lit signage, the whole skydome), and its sibling `flags.fog: false` opts 225 of them out of distance fog. Applying SUNLIGHT to those anyway dims self-lit art to invisibility on a night map; see [gamez.md](gamez.md) for the census and `SceneBuilder`'s per-model shader variants for the mapping.
- **Terrain UVs are a mirrored triangle wave, not a sawtooth.** U rises to exactly 1.0 and folds back rather than wrapping to 0; surfaces whose UVs stay in [0,1] must use **CLAMP** sampling. Apply this per surface: 54% of surfaces genuinely tile (U reaches 407), so blanket clamping changes C5 city rendering. See `SceneBuilder.UvsWithinUnitSquare` and `docs/architecture.md`.
- Polygons carry a signed **draw priority** (v0.6.1 `unk04`, upstream `priority`); equal priorities resolve by **draw order, later wins** (polygon list order within a mesh, flat nodes.json order across nodes). Ignoring either z-fights every decal, SceneBuilder maps both to depth bias.
- Polygon flag **`unk3` (`0x0800`) is `no_clutter`**: a node-name substring artists author (`gg_load.c` checks for `no_clutter`) gates `ClutterBuilder` scatter (`GameZPolygon.NoClutter`). In a coplanar pair, the flagged layer is the measured overlay and receives `SceneBuilder.NoClutterLayerBias`; this is a second layering axis, not a `priority` value. A base/flagged-overlay pair can resemble a day/night or LOD variant set; compare UV scale and vertex colour before assuming duality.
- Polygon flag `unk2` (upstream `SHOW_BACKFACE`, bit 0) means double-sided; without it the original backface-culls. The visible side is the CCW loop = Godot's *back* face → `cull_front`. Culling is required: roughly 60% of world polygons are single-sided (C1 40.4% / C5 36.4% carry the flag). It keeps the camera-anchored skydome from drawing over terrain and avoids unresolvable back-to-back z-fights.
- **Sidedness is per POLYGON and nowhere else.** A `materials.json` record is `{texture_index, soil, cycle, flag}`, and that `flag` is not a cull mode: it is set on 215 materials install-wide (134 in `planes`, 38 in C4, 22 in C5, 21 in C3, none in C1, C1B, C1C, C2 or C2B), and every one of them is an aircraft or pilot skin (`hel_wing.tif`, `cphead.tif`, `plane_tire.tif`), never a building or terrain one. So a missing wall is never a material that should have drawn two-sided; look for geometry the walk never reached.
- **The same flag governs COLLISION, and the original's ray test reads it** ([`../org/weaponRay.md`](../org/weaponRay.md)): a single-sided polygon is solid from its visible side alone. `SceneBuilder` honours it per polygon, splitting each surface class into a `BackfaceCollision` shape and a one-sided one whose winding is REVERSED, because Godot's one-sided concave collision is solid along its own face normals and those point at the source's *invisible* side. Collidable population, one-sided of total faces per chapter: C1 8887/13843, C1B 3207/5669, C1C 3032/5360, C2 6171/9916, C2B 2513/4727, C3 8245/11477, C4 9089/14402, C5 11397/16727. **Water is one-sided everywhere** (only C1B authors 6 two-sided water polygons), so nothing under a water or terrain surface can see it overhead: read such a column DOWNWARD from above.
- **Back-to-back pair: one quad, two polygons over the SAME vertex indices in opposite winding, a different material each**, how a one-sided prop gets a front and a back texture (the Hollywood backlot's `fcpan01…33` facade screens: sky inside, wood framing outside). They are *exactly* coplanar, so no depth bias can ever separate them; only backface culling can, which is what the original relied on. 266 pairs game-wide, concentrated in C2 (71) and C5 (172), never assume a duplicated vertex set is redundant geometry to weld or drop.
- **`cull_front` inverts aircraft lighting unless the shader cancels it.** Every visible aircraft fragment is back-facing, and Godot negates `NORMAL` on back faces. The file normals are correct, but light calculation needs `NORMAL = -normalize(...)` in the shaded path. The fullbright world path does not read `NORMAL`.
- **A glTF export has to reverse the winding.** glTF's front face is the CCW loop full-time; there is no winding switch the way there is an up axis, and Godot's writer already flips every triangle on the way out to map its own CW-front convention onto glTF's. Over data whose visible side is Godot's back face, the two together write the model inside out. `GltfExporter` reverses each exported surface instead of disabling culling: two-sided materials hide the inversion, but leave every interior surface drawn over its exterior and every back-to-back pair z-fighting.
